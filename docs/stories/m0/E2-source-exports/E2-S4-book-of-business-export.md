## User story

As a contributor, I want a hand-maintained-style Excel workbook, so that datasets include the spreadsheet every real firm keeps on the side, with its habits and inconsistencies.

## Context

The book of business is maintained by operations staff, not generated by a system. It has title rows, spacer rows, one sheet per advisor, an archive sheet, and balances typed by hand and left stale. It is also the first place a reader would see `AcctNo` as a header. It is the lowest-priority source in the roadmap's authority rules.

## Scope

**In scope**
- A `BookOfBusinessExporter` producing one `.xlsx` workbook.
- A shared helper that makes the workbook byte-for-byte reproducible.

**Out of scope**
- Formulas, charts, and conditional formatting beyond light cosmetics.
- Mess beyond the source's inherent habits (E3).

## Technical design

### Workbook structure (`book_of_business.xlsx`)

| Sheet | Content |
|---|---|
| `Summary` | Count of households and total balance per advisor, as plain values (not formulas) |
| `Advisor - <Name>` (one per advisor) | The households and accounts of that advisor |
| `Archive` | Closed accounts and departed households, same columns |

Layout of each advisor sheet:

- Rows 1 to 3: title (`Lantern Ridge Wealth Partners - Book of Business`), `Advisor: <name>`, `Updated: <date>`.
- Row 4: blank.
- Row 5: header.
- Data from row 6. A blank spacer row follows each household's block. The household name appears only on the first row of its block (the following rows leave it empty), as people tend to do.

### Columns

| Header | Concept | Format |
|---|---|---|
| `Household` | `household.name` | `Smith, John & Jane` style, first row of block only |
| `Advisor` | `household.advisor` | advisor name |
| `AcctNo` | `account.number` | stored as text with a leading apostrophe-style text format |
| `Type` | `account.type` | short text (`Joint`, `Roth`, `IRA`, `529`, `Indiv`) |
| `Balance` | `account.balance` | rounded to the nearest 100, Excel currency number format |
| `Notes` | `meta.notes` | sparse free text from a small phrase list (`needs W-9`, `moving to new address`) |
| `Last Review` | `meta.review_date` | Excel date serial with `d-mmm-yy` format |

Balances are deliberately **stale and rounded**: each balance is drawn as truth balance multiplied by a small drift factor (a normal draw clamped to about plus or minus 12 percent) and rounded. Drift is part of the inherent style here. Larger, intentional mismatches belong to E3-S6.

Inherent drift and rounding are controlled by a setting, `book_of_business.inherent_drift` (maximum drift fraction, default `0.12`) with a companion `round_to` (default `100`). The `clean` preset sets drift to `0` and `round_to` to `0.01`, so a clean dataset has no value differences at all. This keeps the discrepancy answer key (E5-S4) at zero for `clean`.

### Deterministic output

`openpyxl` writes the current time into the workbook properties and into the zip entry timestamps, which breaks reproducibility. A helper `save_deterministic(workbook, path)` must:

1. Set `workbook.properties.created` and `modified` to a fixed datetime derived from `as_of_date`, and `creator`/`lastModifiedBy` to constants.
2. Save to an in-memory buffer.
3. Rewrite the zip with every entry's `date_time` set to `(1980, 1, 1, 0, 0, 0)`, entries in sorted order, and fixed compression, then write to disk.

### Locators

Rows are located by `(file, sheet, excel_row_number)`. The writer accounts for the title rows and spacer rows.

## Acceptance criteria

- [ ] Workbook has a `Summary`, one sheet per advisor, and an `Archive` sheet.
- [ ] Advisor sheets have title rows, a header on row 5, and spacer rows between households.
- [ ] Household name appears only on the first row of its block.
- [ ] Balances are rounded and differ from truth by drift; none are zero or negative.
- [ ] Account numbers are stored as text (leading zeros preserved).
- [ ] Generating the workbook twice produces byte-identical files.
- [ ] The README's `AcctNo` header example is present.
- [ ] Locators return the correct sheet and Excel row.

## Test plan

- Open with `openpyxl`, assert sheet names, header positions, and blank spacer rows.
- Byte equality test across two runs, run in CI on both Linux and Windows.
- Test that closed accounts land on `Archive` and not on advisor sheets.
- Locator test against loaded cells.

## Risks and notes

- Byte determinism can regress when `openpyxl` is upgraded; the E4-S5 guard catches it.
- Merged cells would complicate downstream reading; avoid them in M0.
