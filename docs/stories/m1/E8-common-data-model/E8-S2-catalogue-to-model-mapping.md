## User story

As a contributor, I want every concept in the catalogue mapped to a place in the model, so that every source column has a place to land and nothing is dropped by accident.

## Context

The catalogue has 27 concepts (more after holdings arrive in E9). This story ties them to the model defined in E8-S1 and makes the tie checkable, so adding a catalogue concept later fails a test until someone decides where it goes.

## Scope

**In scope**
- A mapping table in `docs/data-model.md`: each concept id, the entity and fact it lands in, or "not carried over" with a reason.
- A machine-readable copy used by later ingestion stories.
- A guard test that the mapping and the catalogue agree.

**Out of scope**
- Mapping a source's actual column to a concept (that is the M0 `column_mappings` answer key, and M2's suggestion work).

## Technical design

- Mapping file `src/onboardkit/model/concept_map.yaml`: a list of entries with `concept`, `entity`, `fact`, or `carried: false` with `reason`.
- Loader `onboardkit.model.concept_map` returning a typed structure (Pydantic).
- The table in `docs/data-model.md` is generated by `scripts/model_mapping.py` from the YAML, the same way the mess catalogue is generated; a test fails when the document is stale.
- Guard `tests/model/test_concept_map.py`:
  - every concept id in `concepts.yaml` appears exactly once in the map;
  - no map entry names an unknown concept;
  - every `entity` and `fact` exists in the model definition (a list kept in `model/entities.py`, which E8-S4 builds on);
  - every `carried: false` entry has a reason.
- Expected not carried over: `meta.review_date`; `meta.notes` is kept as a source note rather than a fact. Decide and document.

## Files to create or change

- `src/onboardkit/model/__init__.py`, `entities.py`, `concept_map.py`, `concept_map.yaml`
- `scripts/model_mapping.py`
- `docs/data-model.md` (generated mapping section)
- `tests/model/test_concept_map.py`
- `CONTRIBUTING.md`: add a line to the "add a source column" recipe to add the concept to the map.

## Acceptance criteria

- [ ] Every concept in `concepts.yaml` has exactly one mapping entry.
- [ ] Each entry names an entity and fact that exist in the model definition, or is marked not carried over with a reason.
- [ ] The mapping table in the document is generated, and a test fails if it is stale.
- [ ] Adding a concept to the catalogue without mapping it fails a test with a message naming the concept.
- [ ] The recipe in `CONTRIBUTING.md` mentions the mapping.

## Test plan

- Guard tests above, plus a test that removes an entry in memory and expects the failure message.
- Run `scripts/model_mapping.py` twice and compare output (stable).

## Risks and notes

- The entity list in code and in the document must not drift: the document's entity names are checked against `entities.py` in the same guard.
